# AGENT_RULES.md — Replit Agent実装ガードレール

文書版: 0.1.0 / 2026-10-21。**この文書は実装許可書ではない。** 一回につき承認された `ROADMAP.md` のステップ1つだけを対象にする。

## 1. 絶対ルール

1. **1ステップ = 1PR相当 = 1回のユーザー承認**。依頼にない次のステップや将来機能を自動実装しない。
2. 実装開始前に「今回の目的、変更するファイル、変更禁止ファイル、期待するテスト結果、未確定事項」を短く提示する。不明な外部APIや仕様は**質問/保留**。API・データ・テストを捏造しない。
3. 既存動作を壊さないことを最優先。指定されていない画面、フォルダ、依存関係、構成、Gitブランチ、仕様文書、テストを勝手に編集/削除しない。
4. **TICK STREAM未契約**。ユーザーが公式API仕様・権利・認証方式を提示して許可するまでは `LIVE` 接続、キー入力UI、架空のエンドポイント、スクレイピングを実装しない。
5. MOCKには一目で識別できる`MOCK / SIMULATED`ラベルをつける。実データに見せかけた価格、板・取引履歴、接続状態を表示しない。
6. 板数量 `qty` と約定 `volume` は別型・別関数。MBPから注文ID、個別注文、アイスバーグ、ストップ、投資家属性を生成しない。
7. `NO DATA != 0`。欠損を0で埋めて描画しない。Trade aggressorが不明な場合はDeltaを確定させない。
8. フィルター・配色変更でraw eventsを削除/更新/丸めない。保持期間・スキーマ・生データを勝手に変えない。
9. ユーザーの承認なしに注文発注、データ外部送信、クラウドDB移行、テレメトリー、課金、クラウドデプロイを実行しない。
10. 一度ビルド/テストが通っても「完成」と報告しない。ユニットテスト、手動UI確認、既知の欠陥と未対応機能を報告する。

## 2. 仕様・優先順位

- 優先順位: その回のユーザー指示 > `SPEC.md`/`DATA_SPEC.md`/`UI_SPEC.md` の[C] > 当該ステップの`ROADMAP.md` > [P] 初期値。
- [U]項目は**未確定として表示**するかMOCKに閉じ込める。黙って[P]へ格上げしない。
- 仕様が衝突したら実装を止め、該当箇所と案を質問する。テスト期待値を実際のコードに合わせて書き換えてはいけない。
- 契約未確認ベンダーの架空HTTP/WSレスポンスを「公式仕様」として捏造しない。

## 3. 変更範囲の運用

変更可ファイルをステップごとに必ず明示。追加ファイルも事前申告。既存コードの大規模整形・フォルダ全移動・依存アップグレード・大規模リファクタリング禁止。

**プロジェクト目標の想定構成（計画のみ）:**

```
apps/web/                   # React/Vite UI
apps/desktop/               # 後のElectron main/preload
apps/local-gateway/         # MOCK/LIVE受信と永続化のNode側
packages/core/              # 数学とイベント型・状態機械
packages/render/            # WebGL2描画と共通座標
packages/fixtures/          # 決定論的なMOCK/期待値
packages/storage/           # SQLite/バイナリchunkの抽象化
SPEC.md  UI_SPEC.md  DATA_SPEC.md  AGENT_RULES.md
ROADMAP.md  FIRST_AGENT_PROMPT.md
```

実装ステップに必要な場合のみ新ディレクトリを作成。**完成ディレクトリの空ファイル群を一括生成しない。** 将来機能のボタンを見かけ上動かして完成扱いにしない。

## 4. テストと数値の規律

- `DATA_SPEC.md` のfixtureが**唯一の数値オラクル**。変更の度に該当fixtureのテストと既存全テストを実行。
- 価格は整数tick。`NQ: 80000 ticks = 20000.00`, `1 tick = 0.25` をテスト。数量は整数、時刻はUTC epoch ns十進文字列/BigInt。
- TWA fixture: 10秒平均38枚、2秒ビン[60,40,30,60,0]。2Tickで追加20なら58枚。
- Delta fixture: BUY23・SELL4 -> V27・Delta19・imbalance70.37037…%。
- 欠損 fixture: coverage50%は `NO DATA`。0の板と区別。
- テスト失敗時は原因を隔離し、期待値/仕様を勝手に緩めない。テストを削除/skipにして成功を装わない。
- UI画像だけで合否にしない。信頼できるデータ→計算→描画を確認する。

## 5. 接続・セキュリティ

- MOCK以外のデータ元に接続するコードを、明示的に認可されるまでは追加しない。
- 資格情報をReactの `VITE_*` やレンダラに持たせない。Replit Secretsは後のNodeサーバー側だけ。本番はOS資格情報ストア。
- Gitへトークン/市場データダンプ/ユーザー固有パスをcommitしない。`.gitignore`で`.env`, `.db`, `.sqlite`, `*.zst`, `market-cache/`, `dist/`, `node_modules/`等を除外（テストfixtureは許可）。
- Electronでは `nodeIntegration:false`、`contextIsolation:true`、`sandbox:true` と限定preload APIを必須にする。
- ユーザー許可なしに外部GitHubへpush・デプロイ・サーバー公開しない。

## 6. 実装手順テンプレート（Agentが毎回書くこと）

### 開始前

1. ステップID/目的と非対象
2. 変更するパス（新規/修正）
3. 変更しないパス・機能
4. 利用するMOCK fixture
5. 期待数値と品質状態
6. 実行予定コマンド
7. 新規依存と理由（ある場合のみ）

### 作業中

- 先にテスト/型を作り、必要な最小変更のみを行う。
- 既存コンポーネントに仮の売買注文機能を追加しない。
- ランダム値の動作確認より、決定論的fixtureの再現試験を優先。
- 不明な外部仕様・不足権限・依存バージョン不整合があれば停止して報告。

### 完了報告（必須）

```
Step: <ID>
変更ファイル: <一覧>
実装した内容: <事実のみ>
今回実装していない内容: <一覧>
コマンド/テスト結果: <パス/成功件数と失敗件数>
fixture計算結果: <期待=実測を明記>
手動確認: <操作と観察結果、未実施ならその旨>
既知の制限・不具合: <一覧>
次の提案: <次の1ステップだけ。自動着手しない>
```

## 7. PR/コミットとレビュー

- 変更差分をユーザーに提示してから次工程へ。作業途中でも破壊的変更を避け、ロールバック方法を明示。
- 依存ロックファイルの変更は説明、理由のない依存導入はしない。
- `npm audit`等の自動修正で大規模依存アップデートを勝手にしない。
- プロダクト名/ロゴをDeepDOM/Bookmapと同一にしない。独自仮称 `Orderflow Lab` を使い、名称確定後差し替える。

## 8. Stop条件

以下で実装作業を中断し、ユーザーに判断を求める。

- ユーザー要求の計算とベンダーデータ形式が矛盾する。
- ファイル変更範囲を超えないと実装できない。
- 既存テストが修正前後に失敗し、原因が特定できない。
- 実データ接続・資格情報・市場データライセンスが必要になる。
- UI上でMOCKとLIVEの区別がなくなる。
- 欠損時に0を使わなければ実装できないと判断した。
- 生データを完全に保存できず黙って取りこぼす危険がある。

**この規則はロードマップ全工程に適用し、ユーザーが明示的に変更するまで有効。**
