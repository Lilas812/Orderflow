- [R00変更範囲の承認](r00-scope-approval.md) — Preview登録用の追加設定のみ承認済み。以降の工程や範囲拡大には別途承認が必要。
- [Volume ProfileのValue Area契約](volume-profile-value-area-policy.md) — 70%、POC起点、隣接tick比較、同量は両側。ゼロ区間の省略でも同じ境界を維持する。
- [補助コマンドと実行環境](runtime-scope.md) — 未導入コマンドの自動構成変更を避ける。Linuxの終了済み子と稼働中のRSS測定不能を区別する。
- [WebGLの検証環境](webgl-verification.md) — 標準テスターはGL無効の場合がある。実WebGLのバッファ・画素検証と物理GPU性能を区別する。
- [相対基準の品質方針](relative-baseline-policy.md) — R07は承認された保守的な300秒全域観測を条件とする。暫定固定を正式な基準と表示しない。
- [テスト診断のログ表示](test-diagnostic-output.md) — 成功テストの表が出ない場合は表示経路を分離し、明示フラグ付きの診断実行で確認する。
- [約定の訂正・取消方針](trade-revision-policy.md) — 適用処理はベンダー仕様確認後に別工程で設計する。遅延新規Tradeの再集計とは区別する。
- [視覚統合の承認方針](visual-clustering-policy.md) — 品質区間のイベント時刻対応を推測しない。連鎖の最大統合範囲は別途承認なしに追加しない。
- [独立MOCKの比較方針](independent-mock-comparison.md) — F-04/F-05は別Store・別セッションのまま共通UTC軸で比較する。単一セッションとみなさない。
- [共通Viewportの変更条件](shared-viewport-approval.md) — 既存座標変換式の変更が必要な場合は、実装前に理由と影響範囲を報告する。
- [設定保存の境界](settings-storage-boundary.md) — 開発用JSONは既存Vite内だけ。workspace内の隠しフォルダーを非公開領域とみなさない。
- [SQLiteのWAL安全性](sqlite-wal-safety.md) — ドライバー名ではなく実際のSQLite版を確認し、WAL-reset問題の修正版を選ぶ。
- [保持期限と復元状態](retention-state-boundary.md) — 原本削除だけでは不十分。復元状態・重複判定情報に古いイベント全文が残らないか確認する。
- [R16実行構成の承認境界](r16-runtime-boundary.md) — 有限CLIと試験IPCのみ承認。常駐化・ブラウザ実接続・新規APIには別途承認が必要。
- [測定結果の根拠保持](measurement-evidence.md) — 一時領域の出力だけに依存せず、除外済みworkspace内へMOCK計測ログを保存する。
- [LIVE受信・保存の許諾境界](live-trial-permission.md) — デスクトップRAM受信は条件付き承認。キーのquery格納禁止。旧Ticks保存許諾をL2へ拡張しない。
- [デスクトップ製品方針](desktop-product-direction.md) — 最終ターゲットはWindows 11／Electron。Webは既存資産・検証基盤として再利用し、Linux起動をWindows保証としない。
