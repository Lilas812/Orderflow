# 空・部分履歴の取得済み判定と方向不明約定の修正

## 報告

- 実施内容：履歴の要求範囲と実受理範囲を分離し、N約定を既存の `side:"unknown"` として受け付ける修正・隔離試験を実施。保存調査は読み取り専用。
- 変更ファイル：下記「変更範囲」参照。画面の製品コード・保存形式・設定・依存は変更していない。
- 確認手順：下記の再現コマンドと再取得手順。今回、公開URLへの確認・設定操作はしていない。
- 実行した確認：server 383/384、失敗は指定された既知LONG VP 1件。画面側206/206、型検査・隔離ビルド合格。
- 仕様との差分：RESTの空・部分応答を要求範囲全体の取得済みにしない今回の指示を適用。仕様書本文は変更していない。ライブの静かな秒に関する既存の承認済み判定は維持。
- 未解決・懸念：既存の誤ったcoverage・空ファイルは未修復。今回の公開だけで過去データが直るとはしない。空ファイルを作成した当時の全実行経路はログ不足で確定していない。
- 次の候補：週末の公開後、別途承認を得て、保全・書込排他・取得元の完全性確認を伴う過去区間の修復。

## 変更範囲・原因・原状復帰

作業開始時HEAD：`b768cb7`。最終確認時の既存HEADは `780b8b7d8408082adf1c0061d4e863d7ceca4158`。
その間にコミットされた既存HEATMAP描画変更も保持した。今回の変更前、次の経路で問題を再現できた。

| ファイル・関数 | 問題と今回の変更 |
|---|---|
| `server/src/history/backfill.ts` `Backfill.take()` | 空応答をnoDataに記録した後も処理が進み、最後に要求全体をmarkCoveredしていた。空では保存・取得済み化せず、部分応答はデコード成功した秒だけを採用する。残りは `unobserved_history_seconds`。 |
| `server/src/vp/trade-history.ts` `readTradeRange()` | VP用の別経路でも要求窓全体を採用・apiSecondsへ加算していた。空なら未採用、部分なら観測した秒のみ採用・計数する。 |
| `server/src/store/local.ts` `insertTradeRange()` | 空の補完でも要求窓を取得済みにしていた。空は無操作とし、非空でも受理した秒のみを、データ置換後に索引へ記録する。新規行のない隣接時間は置換しない。 |
| `server/src/history/evidence.ts` `observedRanges()` | 実在秒を重複なく連結する共通処理。時刻の巻き戻りは保持し、未観測秒をつながない。 |
| `server/src/ingest/normalize.ts` `normalizeTradeSide()` | `buy/sell/N/unknown` を受理し、後二者を既存の `unknown` に正規化。それ以外・欠落は拒否する。 |
| `server/src/ingest/receiver.ts` `trade()`、`server/src/history/decode.ts` `historyTrades()` | 従来buy/sell以外を拒否していた入口を上記へ統一。ライブ・通常履歴と、同デコーダーを使う履歴workerに適用。 |

保存JSONに新しいside値を追加していない。既存の `unknown`・VPの `undirected` を再利用する。
件数や同内容の別約定を重複除去しない。既存行の内容・順番・限月は変えない。
取得済み秒は「受理した秒の証拠」であり、その秒の全CME約定を受信した保証へ意味を広げない。

原状復帰は今回のコミットのコード差分のrevert。今回、過去データの変更がないためデータの巻き戻しは不要。
公開後のデータ訂正を別途行った場合、その訂正はコードrevertとは別に、保全した索引・世代から戻す必要がある。
稼働中の受信・サーバーを停止・再起動していない。Publishも実施していない。

## 方向不明数量と画面

## 再取得の手順案（今回は実行していない）

1. 週末にユーザーが修正版を公開し、別途修復を承認する。既存の誤った索引は公開だけでは直らない。
2. 修復直前に対象のcoverage・時間ファイルの原本、世代・ハッシュ、更新前の範囲を保全する。
   稼働writerと競合しない排他・保守時間を確保する。外部からのCASだけでwriterの古いキャッシュを安全に更新できるとはしない。
3. 上表を最新の読み取りで再確認し、休止区間を区別する。実レコードがある時間・銘柄・他のcoverageは外さない。
4. 確認した空区間だけを、保全済みcoverageの作業コピーで未取得に戻す。空ファイルや元データの一括削除・設定リセットはしない。
   書込先への反映はwriterの排他と世代照合付きで行い、元の索引を復元できるようにする。
5. 対象銘柄・限月・UTC区間を明示して隔離先へ再取得する。既存の `HistoryClient.get()` は `/v1/history/ticks` または `/v1/history/book`。
   過去区間は起動時の直近3時間取得だけでは回復しない。APIの保持範囲・現契約・空/切詰め応答を確認し、対応外ならそこで止める。
   約定は既存購入データを利用できる場合も、限月・区間・完全性を先に照合する。約定で板は復元しない。
6. 保存後の読戻し・件数/枚数/価格別・N数量・範囲外の行保全を照合してから、取得できた秒だけを索引へ反映する。
   空応答のままなら未取得を維持する。同じ入力の再実行で増えないことも確認する。
7. UIの取得範囲・品質表示と、VP・FOOTPRINT・CVD等の再集計を確認する。失敗時は保全した世代・索引へ戻す。

これは実行可能性と排他を確認するための手順であり、無承認の本番索引書換スクリプトは追加していない。
