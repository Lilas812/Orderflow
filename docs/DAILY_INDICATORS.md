# HEATMAP 最新表示・日次CVD／VWAP（2026-10-30）

ユーザー承認による、SPEC.md・UI_SPEC_HEATMAP.md の関連部分の補足。LONG VPの週指標とは別。

- 対象はNQ／GCのHEATMAP。既存250msの約定配信は初期履歴取得を待たず送る。履歴との同一性照合は従来の受信識別子を維持する。
- 最新価格・形成中の約定はrequestAnimationFrameで描く。重い板描画が同時に必要なら最新約定を先のフレームで描く。通常前景の受信→最新描画p95は100ms以内を目標とし、冷間起動の値は別記する。
- 追従中の時刻基準は最新の確定板と受信約定の新しい方。過去閲覧は動かさない。板ビットマップの移動だけでは再色付けしない。約定自身の時刻は変えない。DATA AGEは受信時点での実時刻との差を表示する。
- CT17:00（America/Chicago、DST対応）で日次リセット。既存セッションVPと同じ入力・履歴所有境界を使う。CVD＝累積買い主導枚数−累積売り主導枚数。VWAP＝累積（価格×枚数）／累積枚数。バブル閾値前の全約定を採用し、2時間や表示範囲で切らない。
- 秒別の数量・価格加重和をサーバーで保持し、既存履歴取込の結果を共用する。別の履歴ジョブ・毎秒全履歴取得は追加しない。未取得データは生成しない。
- `daily=1`を指定する新クライアントに限り、同じWSで`sessionIndicators`を送る。銘柄・セッション・revision付きの絶対値で秒を置き換える。初回／世代変更／差分保持範囲外は全量、それ以外は既存250ms周期の差分。旧クライアントの配信は増やさない。
- 秒別差分の参照記録は最大512秒分とし、範囲外のクライアントには全量再同期する。これは保存期間やデータ間引きではない。
- リプレイは仮想再生位置までの既存VPから構築し、未来の約定を含めない。銘柄切替・再接続時は前の状態を破棄する。
- VWAPは黄色（既存パレットの`#ffd60a`）の価格線。DELTAを残し、下段のDELTA／CVDは高さ1:1。CVDには価格軸と独立した枚数軸を設ける。CVDをオフにすると下段はDELTAのみ。
- 初期表示は両方オン。個別切替はsessionStorageでそのタブ内に保持し、設定PUTや共通設定versionを増やさない。
- 過去の描画は可視範囲のキャッシュ、最新末尾は約定バッチで描く。後着の秒別絶対値はその後の累積も更新する。
- 履歴取込中は「途中集計」、完了後も保証できない欠けを隠さず「取得分」と表示する。日次VWAPは受信価格の未調整値であり、限月の補正を捏造しない。限月不明の数量を明示する。
- 新サーバーに指標機能がない場合は「日次配信未対応／未受信」と表示し、空表示を成功としない。
- 本件は隔離環境での実装・検証。公開環境の実ライブ確認・公開反映は別途必要。
