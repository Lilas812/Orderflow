## 1. 目的と範囲

- 長期の値動きと出来高の偏りを観察する画面を作る。日ごと・週ごとの VP を価格チャートに貼り付けて並べ、週VWAP と週CVD を合わせて見る。【確定】
- ヒートマップの画面とは別の画面にする。同じサイト・同じサーバー・同じサインイン（Invite only）。この画面にヒートマップは出さない。【確定】
- 銘柄は NQ だけ。【確定】
- 作る順番：先に蓄積（Phase 13a）を作って公開先で動かし始め、画面（Phase 13b）はそのあと。画面を作っている間もデータを溜める。【確定】

## 2. 時刻と区切り【確定】

- 時刻の表示は、ヒートマップの画面と同じ設定 `timeZone`（初期値は日本時間）に従う。
- 区切りは取引所の時刻で決める。米国中部時間（CT）と東部時間（ET）は常に1時間差なので、どちらで書いても同じ瞬間になる。
  - 取引日：CT 17:00 〜 翌日 CT 16:00（ET 18:00 〜 17:00）。SPEC 7.4 のセッションと同じ。取引日の日付は、終わる側の日付（CT）にする（例：日曜17:00〜月曜16:00 は月曜の取引日）。
  - 休止：CT 16:00 〜 17:00。休止中に約定があれば、終わる側の取引日に含める（SPEC 7.4 と同じ）。
  - 週：日曜 CT 17:00 〜 金曜 CT 16:00（ET 日曜18:00 〜 金曜17:00）。
  - RTH：CT 8:30 〜 15:00（ET 9:30 〜 16:00）。
- 夏時間の切り替えで、区切りの日本時間は1時間ずれる。

## 3. データ（Phase 13a）

### 3.1 元データと保存先【確定】（2026-10-29 ユーザー決定）

- 元データは、すでに保存している約定のファイル（SPEC 9 節。公開先では App Storage の `prod/trades/…`）。長期VPのために TICK STREAM へ別に接続しない。
- 集計した結果も App Storage に置く。PostgreSQL などのデータベースは使わない（保存の仕組みを1つにし、費用を月数十円に抑えるため）。
- 開発では今までどおり無効にし、試すときだけ環境変数で有効にして `dev/` に書く（SPEC 9 節「公開時の保存」と同じ分け方）。

### 3.2 初回の取り込み【確定】

- 公開先で初めて動いたとき、直近7日（TICK STREAM の履歴で取れる範囲）の約定をそろえる。
- そろえ方は、SPEC 9 節の「VP のための約定の取り込み」と同じ（`coverage.json` で足りない区間だけ、15分以下の窓、半開区間、`truncated` なら半分、1窓ずつ、今に近い窓は5分待つ、再試行3回、既存のファイルに組み込む）。
- そろったあと、終わった取引日ごとに 3.3 の集計を作る。7日より前は取れないので、そこが蓄積の起点になる。

### 3.3 取引日の集計【確定】

1取引日につき1つのオブジェクト：`{prod|dev}/longvp/NQ/days/{取引日 YYYY-MM-DD}.json.gz`

中身（価格はすべてティックの整数で、限月の生の値。調整しない）：

| 項目 | 内容 |
| --- | --- |
| `version` | 1 |
| `tradingDate` | 取引日（YYYY-MM-DD） |
| `startSec`・`endSec` | 取引日の始まりと終わり（Unix 秒、半開区間） |
| `contracts` | `[{contract, fromSec, toSec}]`：その取引日に使われた限月と期間 |
| `bars1m` | `[[分の始まりの秒, 始値, 高値, 安値, 終値, 買い枚数, 売り枚数, 限月の番号], …]`：1分足。約定のない分は入れない |
| `vp30m` | `[[30分の始まりの秒, 価格ティック, 買い枚数, 売り枚数, 限月の番号], …]`：30分 × 1ティックごとの出来高 |
| `gaps` | `[[fromSec, toSec], …]`：約定がそろわなかった区間 |
| `complete` | `gaps` がなければ true |
| `builtAtUs` | 作った時刻（マイクロ秒） |

- 限月の番号は `contracts` の並び順。1分足・30分の行は、その時刻の限月に入れる（3.5）。
- 1日の量の目安：1分足 約1,400行、30分の行は数千〜1万行。gzip で数百KB 以下の見込み（実装で測って報告する）。
- 書き込みは一時ファイル → アップロード → 照合（Phase 10a と同じ）。

### 3.4 日次の処理【確定】

- 同じサーバーの中で、タイマーで動かす。毎日の休止（CT 16:00〜17:00）の間に、終わったばかりの取引日を確定する。
  1. その取引日の約定がそろっているか `coverage.json` で確かめ、足りなければ 3.2 の方法で埋める（7日以内のときだけ）。
  2. 約定のファイルから 3.3 の集計を作り、アップロードする。
  3. 直近7日の取引日のうち `complete: false` のものを、もう一度埋めて作り直す。良くなったら置き換える。
- 週末（金曜16:00 〜 日曜17:00）も、最初の休止の時間に同じことをする。
- ライブの受信と配信を止めない。取り込みは遅くなってよい。
- 7日を過ぎても埋まらなかった区間は `gaps` に残し、画面で分かるようにする（4.3）。

### 3.5 限月と乗り換え【確定】（調整の値の取り方は Phase 13a で調べて決める）

- 限月は、REST の `/symbols` の `contract` と `contractSince` から、時刻で決める（今の実装の方式）。
- 乗り換えの記録：`{prod|dev}/longvp/NQ/rolls.json` に `[{from, to, atSec, diffTicks, method, detail}]` を持つ。`diffTicks` は「新しい限月の価格 − 古い限月の価格」をティックに丸めたもの。
- `diffTicks` の取り方：
  - (a) 履歴の API で限月を指定して取れるなら：乗り換えの前5分のあいだ、両方の限月に約定があった秒ごとに「新しい限月の最後の価格 − 古い限月の最後の価格」をとり、その中央値。`method: "overlap"`
  - (b) 取れないなら：乗り換えの直後の新しい限月の最初の約定 − 直前の古い限月の最後の約定。`method: "edge"`。2つの約定の時刻の差も `detail` に残す（離れているほど不正確）
  - どちらが使えるかは Phase 13a の最初に調べて報告する。
- 保存するデータは生のまま。調整は画面で表示するときだけ行う（4.1）。
- これまでに口頭で伝えた「限月ごとに分ける・足を分ける・VWAP を計算し直す」は、この「表示するときに調整する」で置き換える。

### 3.6 当日の分【確定】

- 当日（確定前の取引日）の分は、サーバーのメモリで 3.3 と同じ形に集計し続ける。App Storage には日次の処理まで書かない。
- サーバーが再起動したら、当日の約定のファイルから作り直す（足りない区間は SPEC 9 節の取り込みで埋まる）。REST で取り直すのは、ファイルにない分だけ。

### 3.7 画面への受け渡し【確定】

- `GET /api/longvp/days?from=YYYY-MM-DD&to=YYYY-MM-DD`：その範囲の取引日の集計（3.3 の形の配列）。1回60取引日まで。
- `GET /api/longvp/today`：当日の分（3.3 と同じ形、`complete: false`）。
- `GET /api/longvp/rolls`：乗り換えの記録。
- サーバーは最近使った取引日の集計をメモリにキャッシュする（上限は実装で決め、メモリの値を報告する）。App Storage にはキャッシュにないときだけ取りに行く。
- 当日の分は、画面が60秒ごとに取りに行く。WebSocket の配信の形は変えない。

### 3.8 状態の表示【確定】

- `/api/status` の `longVp` に：有効かどうか、初回の取り込みの進み具合、確定した取引日の数と範囲、`complete: false` の取引日、乗り換えの記録の数、次の日次の処理の時刻、キャッシュの量。

## 4. 画面（Phase 13b）

細かい値と設定の項目は Phase 13b の前に決める。ここにはユーザーが決めたことを書く。

### 4.1 共通

- ツールバーはヒートマップの画面と同じ（設定と表示リセット）。画面の上部に、ヒートマップの画面との切り替えを置く。【確定】
- 移動と拡大縮小は指・マウスで直接操作する。【確定】
- 乗り換えの調整：長期の画面では、古い限月のデータに、それより後の乗り換えの `diffTicks` の合計を足して、今の限月の価格にそろえて表示する。価格・ローソク足・VP・VAH/POC/VAL・週VWAP に当てる。週CVD は枚数なので変えない。ヒートマップの画面は調整しない。【確定】

### 4.2 レイアウト【確定】

- 上段に価格チャート（期間VP と週VWAP を重ねる）、下段に週CVD。時間軸は共通。
- 上下の比率は境目のドラッグで変えられる。初期値は価格チャート75%・週CVD20%（残りは時間軸）。

| 領域 | 幅 | 高さ | 位置 |
| --- | --- | --- | --- |
| ツールバー | ヒートマップの画面と共通 | 全高 | 左端 |
| 価格チャート | ツールバー以外の全幅 | 約75% | 上段 |
| 週CVD | 価格チャートと同じ | 約20% | 下段 |
| 時間軸 | 価格チャートと同じ | 固定 | 最下部 |

### 4.3 価格チャート【確定】

- 価格は線で描く。ローソク足に切り替えられる。
- 表示の細かさは拡大率に合わせて自動で切り替える（元は1分足）。
- `gaps` がある取引日は、その区間が分かるように示す（例：時間軸の上に薄い斜線）。

### 4.4 期間VP（チャートに貼り付ける VP）【確定】

- 日ごとと週ごとを、手動で切り替える（縮小しても自動では切り替えない）。蓄積がある限り過去まで遡れる。
- 日の区切りは取引日。RTH だけに絞る切り替えも用意する。週は 2 節の週。
- 各期間の左端（区切りの縦線）から右へ、その期間の価格の背面に描く。
- 横幅：最大の棒が期間の横幅の一定割合になるように縮める。基準は「期間ごとに正規化（初期値）」と「全期間共通」を切り替えられる。
- VAH・POC・VAL を横線と価格のラベルで出す。バリューエリア（70%）の範囲を、期間の左端に水色の縦線で示す。POC は次の期間に少しだけ延長する。
- 価格の刻みは設定で変えられる（最小0.25ポイント）。POC・VA は刻みに関係なく0.25ポイントで計算し、刻みを変えても位置が動かないようにする。

### 4.5 週VWAP【確定】

- 価格チャートに線で重ねる。週の始まりで計算し直す。
- 30分×価格の出来高から、Σ(価格 × 出来高) ÷ Σ出来高 で計算する（価格は 4.1 の調整後）。過去の週も同じ方法で再現する。
- 標準偏差のバンドと、前週VWAP の延長は入れない。

### 4.6 週CVD【確定】

- 価格チャートの下に、買い − 売りの累計を線で描く。週の始まりで0に戻す。
- 週の区切りに縦線を引き、価格チャートとそろえる。
- 1分足の買い・売り枚数から1分ごとに描く。今週の分は1分ごとに更新する。

### 4.7 表示の切り替え【確定】

- すべて個別にオン・オフできる：価格（線／ローソク足の切り替えも）、期間VP（日／週、RTH だけ、幅の基準）、VAH・POC・VAL の線とラベル、バリューエリアの縦線、POC の延長、週VWAP、週CVD（オフにしたら下段ごと消して価格チャートを広げる）。
- 切り替えは設定画面に置く（ツールバーには置かない）。設定はサーバーに保存し、端末間で共有する（SPEC 9 節「設定」の仕組みに足す。項目のキーと version は Phase 13b の前に決める）。

## 5. ユーザーの元の仕様からの変更点（2026-10-29）

- 保存先：PostgreSQL → App Storage。約定のファイルが App Storage に残り、再デプロイで消えなくなったため（Phase 10a）。
- 「要確認：生ティック全保存の見直し」：解決済み。約定は1時間ごとの gzip で App Storage に置き、月に約1.5GB・数十円。データベースには入れない。
- 当日の分を再起動で失ったときの取り直し：REST ではなく、まず保存した約定のファイルから作り直す。
- 期間の区切り：ET で書かれていたものを、同じ瞬間の CT でも併記した（SPEC と同じ基準）。
- 時刻の表示：日本時間固定ではなく、ヒートマップの画面と同じ設定に従う（初期値は日本時間）。
