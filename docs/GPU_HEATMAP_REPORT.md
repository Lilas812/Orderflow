## 描画経路

- 既定auto。`?renderer=canvas`で従来経路、`?renderer=webgl`でWebGLを希望する。WebGL2またはfloat描画拡張非対応・寸法上限超過・context喪失ではCanvasへ退避する。
- ヒートマップ本体と現在板の色帯だけ背景DPR=`min(devicePixelRatio,2)`。文字・数字・バブル・価格ライン・点線・VP・DELTA等は従来経路のまま。
- 元の平均化・最大値・既知0/unknown・時間重み・価格面積・有効率は既存CPU集約を共用する。元板や約定、指標の値を変更しない。
- 色の上下限・gamma・LUT・出現6列/取消4列の積・約定で食われた切断・縦Gaussian・横1:2:1をシェーダーで計算する。CPUで色付け済み画像をGPUへ転送する方式ではない。
- CPU前集約とGPU側集約を別実装して比較したものではない。既存の正確な前集約を保持し、色・ぼかし・合成の経路を比較する。
- context喪失では保持中の入力を直ちにCanvasへ全描画する。復帰時はリソースと転送済み識別子を初期化して再構築する。喪失中の`getExtension()`はnullになるため、喪失・復帰試験用拡張は喪失前のハンドルを保持する。

### 結果の解釈

- 命令発行までのCanvas更新p95は全走行33ms以内、受信→命令発行p95は100ms以内。ただし**実GPUの完了・画面表示までの合格証明ではない**。
- SwiftShaderはGL処理をCPUで行う。主スレッドの描画命令発行は短くなったが、総CPUはDPR2で約14秒→265〜268秒/60秒へ増えた。**この環境では省CPUを達成していない。**
- `auto`でSwiftShaderを自動除外するポリシーは追加していない。ソフトウェアWebGL端末では`?renderer=canvas`を使える。自動選択の変更は別判断とする。
