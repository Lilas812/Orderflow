# 研究専用NQ世代の再生成とv2.2再出力

## 範囲・変更・復帰

基準commitは`edff8848102bd38c799c7b111af4a69caa1d64cb`。
今回の変更は研究専用呼出しツール、比較ツール、試験、設定、報告に限定する。
`server/src/`の取込・v2計算・製品コードは変更しない。
学習、モデル比較、売買、Publish、公開設定変更、既存受信の停止・再起動はしない。

新世代は`data/research-v2/nq-purchase-only-01/generation/NQZ26`。
既存の検証済みステージを読み取り専用で再利用し、**空のbaseline**から、

大きな研究出力・購入原本は既存の`data/`除外方針を維持し、Gitへ追加しない。

## 原因照合の方法

旧`data/databento-import/active.json`の時間別install結果と、
旧NQZ26のcoverageを照合する。Nを含む時間と保留時間は重なるので、
時間の和集合を用い、欠け秒を二重に数えない。
Nの時間でも既存baselineのcoverageが残る部分を丸ごと欠けとはしない。

原本索引の全限月における保留B/Aは876,289行。
今回対象の**NQZ26だけでは875,154行**であり、他限月の1,135行を混ぜない。
NQZ26のNは33行・1,476枚。親指定全体のN 38行・1,485枚と区別する。

### 時間別原因と説明できない欠け

全時間の一覧は`data/research-v2/nq-purchase-only-01/hour-causes.csv`（73行）。
UTC時間、CTセッション、Nの有無、保留理由、旧index coverage秒と不足秒を記録した。
内訳はNあり29時間、`existing_contract_unknown`保留46時間、重複2時間。
73時間がすべて丸1時間欠けていたわけではない。
既存baselineが残したcoverageを控除した不足秒の和集合は**111,877秒**。
固定NQグリッド22日分では108,360秒、グリッド外CT10/26の3,517秒を足すと一致する。

実際のv2.2と同じく、coverage indexだけではなく時間gzipの存在も必要とする。
CT10/26では旧NQ index 82,883秒に対して本体付きは79,283秒、
GC index 86,400秒に対して本体付きは82,800秒だった。
両方とも休止のUTC21〜22時にindexだけの3,600秒があり、gzipがない。
この秒を「既知0枚」とせず除外する既存製品読取規則を使った。旧index自体は修正しない。

全23セッションで旧NQ本体付きcoverage 1,709,723秒→新NQ 1,821,600秒。
差111,877秒は上記の2原因と完全一致する（`coverageExplanationExact:true`）。

## 固定グリッドの扱い

`grid-v22.json`から**NQ rootだけ**を変更した新設定を生成する。
計算式・60秒間隔・lookback 1800秒・Y 60/300/900秒・日付分割は変更しない。

GCの入力は変更せず、samples/features/targets/共有historyのGC部分について
全列・全行順序の抽出SHAと件数の一致を検査する。
NQの比較はcoverage・件数・非null率・Y完了率・参照価格なし件数だけに限定し、
X/Yの実値や分布を見て設定・分割を選ばない。
`sourceKind`も固定設定の既存文字列を保持するが、新世代にUI試験注釈や製品行を
コピーしたという意味ではない。新世代は購入データだけで構成する。
