# 購入済みMBO Batch取得ツール

## 実行

認証が成功したユーザーのShellで、次の1行を実行する。依存追加は不要。

```sh
python /home/runner/workspace/scripts/download_mbo_batch.py
```

- 対象ジョブ：`GLBX-20261105-RC8V97S64Y`（固定）
- 原本保存先：`data/research-v2/mbo-01/raw/`
- キーは実行時のShellの `DATABENTO_API_KEY` を使用する。値・認証ヘッダー・URL・サーバーのエラー本文は表示しない。
- このツールが呼ぶAPIは `GET batch.list_files` と、返された購入済みファイルのHTTPS GETだけ。新規ジョブ・購入・ライブ接続の機能はない。

## 容量・再開・照合

1. APIから全ファイル名・サイズ・SHA-256を取得し、一覧と合計サイズを表示。
2. 残りダウンロード量に64MiBの安全余白を加え、空き容量と比較。不足時はデータ取得前に停止。取得中もファイル単位で再確認する。
3. 1MiBずつストリーム保存。途中のデータは `.part` に置き、HTTP Rangeで再開する。再実行時は同じコマンドを使う。接続失敗は最大3回の試行後に停止し、部分ファイルを保全する。
4. 前回の索引と今回のファイル名・サイズ・hashが異なる場合は停止。完成ファイルも毎回hashを照合する。既存の不一致ファイルを自動削除・上書きしない。
5. サイズとSHA-256の一致後だけ完成ファイル名へ原子的に置換し、原本ファイルを読み取り専用（0444）にする。
6. `manifest.json` がジョブに含まれる場合、そのジョブID・全エントリーもAPI一覧と照合。含まれない場合はAPIのファイルmanifestを照合根拠として明記する。
7. Rangeを無視するサーバー、サイズ・hashの不一致、不正なmanifest、同時実行は成功扱いにしない。

中断時は `.part` と索引を残す。`.download.lock` は同時実行防止用の通常ファイルで、プロセス終了時にはOSがロックを解除する。ファイル自体は残す。
ダウンロード済み原本の展開・板の再構築は、このツールでは行わない。

## 保存する結果

すべて `data/research-v2/mbo-01/` 配下（Git・公開対象外）。

| ファイル | 内容 |
|---|---|
| `download-index.json` | API一覧のジョブID・ファイル名・サイズ・期待SHA-256。URLは保存しない |
| `download-verification.json` | ファイルごとの実SHA-256、照合結果、全体状態、経過秒。不一致時は失敗したファイルの実hashも記録 |
| `SHA256SUMS` | 全ファイル成功時に書くSHA-256一覧 |

最終成功条件は終了コード0、かつ `download-verification.json` の `status: "verified"`。
中断・失敗後に以前の `SHA256SUMS` が残る場合も、今回の成功を意味しない。

## 隔離試験

```sh
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s scripts -p 'test_download_mbo_batch.py' -v
```

実API・実キーを使わない試験。正常取得、既存完成ファイルの再照合、manifest不一致、容量不足、短い転送、実行中断と再実行、Range無視・不正応答、hash不一致、危険なパス、シンボリックリンク、リダイレクト時の認証除去、401の秘密非表示、同時実行、空ファイル、GETとBasic認証の構成を確認する。

作成時の実行結果：16件すべて成功（0.204秒）。製品コードの変更なし。実API通信・ダウンロード・ブラウザ／検証サーバー起動は行っていない。

実ジョブのダウンロードはAgentでは実行していない。ユーザーShellでの取得完了後に、Agentが結果ファイルと原本を再照合し、板の再構築・比較へ進む。製品コード・製品保存データ・公開設定・稼働サーバーは変更しない。
