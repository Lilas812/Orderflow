## Key Facts
- React `<Profiler>` `actualDuration` is time spent rendering the profiled subtree for the update; `commitTime` is a timestamp when React committed it. Neither metric is specified as paint, presentation, or GPU-completion timing. [React Profiler](https://react.dev/reference/react/Profiler), saved `01-react-profiler.md`.
- `useLayoutEffect` runs after DOM commit and before browser repaint. This is a pre-paint ordering guarantee—not proof that pixels were presented or GPU work completed. [React useLayoutEffect](https://react.dev/reference/react/useLayoutEffect), `02-react-use-layout-effect.md`.
- `requestAnimationFrame` callbacks run before the next repaint; their timestamp describes the previous frame’s rendering end. Background documents can pause callbacks. A callback alone does not prove that paint, display presentation, or GPU completion occurred. [MDN rAF](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), `03-request-animation-frame.md`.
- MDN WebGL best practices explicitly distinguish API deletion from actual release: deletion releases the API handle, while implementation liveness tracking means the underlying object is freed only once unused. Thus `deleteBuffer`/resource deletion is cleanup evidence, not direct evidence of driver-memory reclamation. `flush()` pushes pending commands for execution; it is not described as completion. `finish()`/synchronous readbacks can wait or stall, but even completion is not evidence of displayed pixels. `getError`/`getParameter` can synchronously stall. [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices), `07-webgl-best-practices.md`.
- `ResizeObserver` device-pixel box provides physical-pixel sizing; callback ordering is after layout/before paint (web.dev). `drawingBufferWidth` is the actual WebGL buffer dimension and can differ from requested canvas dimensions. These are sizing/layout-generation evidence, not presentation evidence. Sources: [web.dev](https://web.dev/articles/device-pixel-content-box), `08-device-pixel-content-box.md`; [MDN drawingBufferWidth](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/drawingBufferWidth), `09-webgl-drawing-buffer.md`.
