## Key Facts

- **`app.quit()` is graceful, not equivalent to `app.exit()`.** Electron v45 documentation says `app.quit()` tries to close all windows, emits `before-quit` first, and emits `will-quit` and normally terminates only if all windows close successfully. It runs page `beforeunload`/`unload`; a window can cancel via `beforeunload`. `app.exit([code])` exits immediately, closes windows without confirmation, and does **not** emit `before-quit` or `will-quit`. [Electron v45 `app`](https://github.com/electron/electron/blob/v45.0.0/docs/api/app.md)
- **Lifecycle event caveats matter to diagnostics.** In the v45 docs, `window-all-closed` is normally emitted when all windows close, but not when quitting via `Cmd+Q` or `app.quit()`; those paths emit `will-quit`. `before-quit` and `will-quit` are not emitted on Windows system shutdown/restart/logout. `autoUpdater.quitAndInstall()` has a documented exceptional ordering for `before-quit`. Same source as above.
- **Window close and destruction differ.** In v45-pinned `BrowserWindow` docs, `close` precedes DOM `beforeunload`/`unload` and `preventDefault()` cancels it. `win.close()` attempts a user-like close and may be cancelled by page code. `win.destroy()` force-closes without page unload handlers or the window `close` event, but guarantees `closed`; after `closed`, drop the reference and do not use the window. [Electron v45 `BrowserWindow`](https://raw.githubusercontent.com/electron/electron/v45.0.0/docs/api/browser-window.md)
- **Renderer and other child-process failure signals are distinct.** Electron v45 `app` docs define `child-process-gone` for unexpectedly disappearing child processes and explicitly say it does **not** include renderer processes. `webContents` has a separate `render-process-gone` event; its details include a reason such as `killed` or `crashed`. Some webContents may share a renderer process, so a crash can affect other associated contents. The docs do not promise that the event itself recreates/reuses a renderer; they say an explicit reload after a forced crash uses a new process. [Electron v45 `app`](https://github.com/electron/electron/blob/v45.0.0/docs/api/app.md) · [Electron v45 `webContents`](https://raw.githubusercontent.com/electron/electron/v45.0.0/docs/api/web-contents.md)
- **Utility process observability.** v45 docs say `utilityProcess.fork()` is available after `app` `ready`; the process has its own `exit` event. Its optional `serviceName` is reflected as the process `name` in `app.getAppMetrics()` and in `app`’s `child-process-gone` event. [Electron v45 `utilityProcess`](https://github.com/electron/electron/blob/v45.0.0/docs/api/utility-process.md)
- **`getAppMetrics()` is app-wide and interval-based.** v45 describes metrics for processes associated with the app. CPU and idle-wakeup values are averages since the previous `getAppMetrics()` call; each call starts a new interval for every process, shared with other main-process code/dependencies. Therefore, independent callers can interfere with interpretation of the interval; this is an implication of the documented shared measurement interval, not a stated prohibition. [Electron v45 `app`](https://github.com/electron/electron/blob/v45.0.0/docs/api/app.md)
- **Playwright’s Electron integration is explicitly experimental.** Electron’s testing guide describes CDP-based experimental support, demonstrates `_electron.launch` in development mode, and says its example was written with `@playwright/test@1.52.0`. Playwright’s API docs also label Electron automation experimental, state supported Electron versions are v21+, and document `electronApp.close()` and `firstWindow()`. These support using Playwright with v45 in principle, not a guarantee for a particular app/configuration. [Electron automated testing](https://www.electronjs.org/docs/latest/tutorial/automated-testing) · [Playwright Electron API](https://playwright.dev/docs/api/class-electron)
- **Harness security settings should preserve the app’s intended isolation.** Electron’s current security guide recommends sandboxing and context isolation for renderers, warns against Node integration for remote content, and says context isolation has been default since v12 and sandboxing since v20. It also states disabling context isolation disables process sandboxing. This is current “latest” guidance, not a v45-pinned security page. [Electron security](https://www.electronjs.org/docs/latest/tutorial/security)

## Notable Claims Requiring Cross-Reference

- For diagnostics, do not treat `app` `child-process-gone` as a renderer-crash feed: the v45 `app` docs exclude renderers, while `webContents` supplies `render-process-gone`. Capture both if both process classes matter.
- A `closed` event alone does not mean a graceful page shutdown occurred: `destroy()` guarantees `closed` while bypassing `close`, `beforeunload`, and `unload`.
- `app.quit()` can be delayed/cancelled by window/page close handling; `app.exit()` bypasses the documented quit lifecycle hooks. A test that needs to observe graceful-shutdown behavior should not use `app.exit()` as a substitute.
- Playwright’s `electronApp.close()` is documented as “Exit app,” but these sources do not specify which Electron quit API/path it invokes or guarantee which app lifecycle events fire. Treat any assumed event ordering as a hypothesis until checked against Playwright implementation/version or an isolated test.
- No source here establishes that Playwright launch defaults preserve a target app’s sandbox/contextIsolation options. The harness should avoid overriding them, but that is a safe design recommendation, not a documented Playwright guarantee.

## Source Quality Assessment

All sources are primary technical documentation: Electron’s version-tagged v45 docs, Electron’s official latest tutorial, and Playwright’s official API reference. The app, utility-process, and BrowserWindow docs are pinned to the v45.0.0 tag; the raw GitHub BrowserWindow/webContents URLs were used after a GitHub HTML fetch returned 429. Electron’s automated-testing and security pages are mutable latest-doc URLs and must not be silently treated as exact-v45 snapshots. The Electron v45 utility-process fetch reports a page date of **October 13, 2026**; other fetched outputs did not provide a reliable publication/update date. Treat absent dates as **unknown**. The Playwright testing guide identifies `@playwright/test@1.52.0` for its example, not necessarily the current or installed version.

## Gaps / Unanswered Questions

- No evidence collected here identifies the app’s installed Electron or Playwright versions/configuration, nor verifies its runtime event sequence.
- Exact v45 documentation for sandbox/contextIsolation defaults was not fetched; the latest security page attributes defaults to v12/v20, respectively, but that is not a direct v45-pinned security reference.
- No evidence proves how the specific Playwright release’s `electronApp.close()` maps to Electron `quit()`/`exit()` or which lifecycle events it triggers.
- `render-process-gone` documentation does not specify automatic restart/reuse behavior after an unexpected exit; only explicit reload-after-forced-crash is described.
- `getAppMetrics()` provides a snapshot/interval, not a documented durable process inventory or event history; no guarantees about sampling cadence/collection latency were established.
