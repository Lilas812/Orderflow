# 長期VP画面（Phase 13b）

## 報告

- 実施内容：同じNQ Heatmapサイトに `/?view=longvp` を追加。上部の切替でヒートマップへ戻れる。長期VPではヒートマップ用WebSocketを開始しない。日次・週次VP、価格線・ローソク足、週VWAP、週CVD、設定・表示リセットを実装。
- 対象：`docs/LONGVP_SPEC.md` 4節。Phase 13aの蓄積、既存の生約定・列・集計保存形式、上流WS、DB、公開設定は変更していない。Phase 10c・11の機能を追加していない。
- 確認手順：ヒートマップ上部の `LONG VP` を押す。設定で日／週、価格線／ローソク足、RTH、幅基準、刻み、装飾・週指標を変更し保存する。別タブで再読込すると保存値になる。価格・時間を直接ドラッグ／ズームし、境界ドラッグで上下比率を変える。CVDオフで下段が消える。リセットは設定値を変えない。
- 開発では蓄積APIが既定で503となる。その場合は「サーバーで無効」と明示する。公開で蓄積されていることを開発の空画面から推測しない。表示用のダミーは製品コードに含めない。

## 設定の分離と保存保護

- `GET/PUT /api/settings/longvp`、文書は `{version:1, values, updatedAt}`、PUTは `{values}` の全項目。値や余分な項目が不正なら400で保存しない。JSON不正も400。読取／保存通信失敗は500。
- ローカルは `data/settings-longvp.json`、App Storageは `{prod|dev}/settings-longvp.json`。本番・開発の選択は既存の保存環境判定に従う。
- 一時ファイルへの書込・fsync後に置換。クラウドは一時ファイルからアップロードし、再ダウンロードのSHA-256一致後だけ成功応答にする。
- 壊れた文書は初期値で読み、ログと `/api/status.longVpSettings` に異常を表示する。保存前に原本を `settings-longvp.corrupt-<Unixµs>.json` へバイト不変で退避する。クラウド退避も再DL照合し、退避失敗なら原本を上書きしない。自動削除しない。
- 既存 `/api/settings` はGETで共通の `timeZone` を読むだけ。既存設定・version・破損ファイルは変更しない。
- ユーザーの「今は2」という説明に対し、着手時点のコードは既にversion 3だった。今回これを2に戻すことも、4や5へ移行することもしていない。

## 仕様にない値

### ユーザー承認値

- 長期VP設定を既存設定から分け、専用API・専用ファイル・専用version 1とする。
- 初期表示：直近10取引日。最大棒幅40%、期間ごと正規化、表示刻み1ティック（0.25ポイント）、価格線、日次VP、RTH限定オフ。他の表示項目はオン。
- 最大棒幅：10〜80%の整数。表示刻み：1〜40ティックの整数。POC・VAはこの刻みに関係なく1ティックで計算する。
- POCの延長：次の取引期間幅の10%まで（週末の休場をまたぐ場合も次の取引期間へ届かせる）。週VWAPは黄色 `#ffd60a`、陽線 `#3ddc84`、陰線 `#a64dff`。VA縦線は水色、週CVDは白。他は既存画面の色を踏襲。
- 縮小で同じ1画素行へ入る出来高は最大値ではなく合計する。
- 未知のロール差を0とみなさず「調整不能」と表示する。該当価格・足・VP・VWAPの行を省き、価格調整不要のCVDは残す。省略した日数も表示する。

### 実装の細部

- 設定キー：`showPrice`、`priceStyle`、`showVp`、`vpPeriod`、`rthOnly`、`vpNormalization`、`vpWidthPct`、`vpTickGroup`、`showVah`、`showPoc`、`showVal`、`showValueArea`、`showPocExtension`、`showWeeklyVwap`、`showWeeklyCvd`。
- 足：1・2・5・15・30・60・120・240分。線は1.5 CSS px、ローソク足は5 CSS pxを満たす最小の足。UTC基準で区切る。価格線は3本分を超える間隔、CVDは3時間超または週境界で線を切る。
- 上下比率：75:20、時間軸5%（最低20 CSS px）。境界ドラッグ範囲は時間軸を除いた高さの30〜90%。境界位置は保存しない。
- 時間表示幅：30分〜90日。過去への移動自体は蓄積のある限り制限しない。未来への表示は現在＋3日まで。
- 価格の初期自動範囲：可視足の高安に8%（最低4ティック）余白。価格方向のドラッグ・拡縮で自動を解除し、リセットで再開。最小表示価格幅8ティック。
- 週の先頭からの合計を失わないよう、可視範囲の属する週の先頭から日次を取得する。1回最大60取引日、キャッシュは160日を目安に遠い日から削除する。
- 期間ごと／共通の棒幅の分母は、描画行の最大出来高／可視期間全体での最大出来高。画素への合算後に決める。
- 週VWAPは30分区間の終わりに累計を描く。週CVDは1分足の終わりに累計を描く。RTH切替はVPだけに適用し、週指標をRTHに絞らない。
- 日次通信は30秒、当日・ロールは15秒、設定は10秒でタイムアウト。エラー・503後に同じ要求を無限再送しない。明示的な再試行で復旧できる。欠けた／不完全な保存日も再試行で再読込できる。
- 当日APIは60秒ごと。画面破棄時はタイマー・日次・当日・ロールの通信を停止する。新画面自体からWSを作らない。
- ホイールは時間方向、価格軸上では価格方向。ピンチは時間方向。ダブルクリック／ダブルタップとツールバーのリセットは初期表示へ戻す。

## 実行した確認

- サーバー全151試験成功。専用設定6試験はローカル／クラウドの独立性・入力不正で原本不変・再読込・破損退避・アップロード失敗・照合不一致・退避失敗時の上書き停止・読取500を確認。
- 画面全129試験成功。両パッケージの型検査成功。最後の追加試験は、週末をまたぐPOC延長が次の取引期間の10%まで届くことを確認。
- 管理ワークフローで本番ビルド成功（47 modules）。ローカル保存初期化は約3分を要したが、保存を消さず起動完了。`server_listening` と `upstream_disabled: production_only_rest_development` を確認。
- 実HTTPで専用設定version 1／初期値を取得し、長期VP当日503を確認。実画面の503表示を撮影：`data/long-vp/phase13b-disabled.jpg`。想定されたAPIの503以外に画面の例外はこの撮影では出ていない。
- 起動後の開発サーバー測定例：RSS 385,724,416 bytes、採取時の上限も同値。これはWorkspaceの一時点であり、本番2GiBの長時間安定性の証明ではない。
- ブラウザの一連の確認は1回実施し成功。ヒートマップ→長期VP→設定保存→再読込・別コンテキスト→拡縮・リセット・CVD境界→ヒートマップ復帰を確認。長期VPでは新しいWSなし。JavaScriptの画面例外なし。1回の要求は最大50取引日で上限60以内。
- 実APIで503を確認後、3つの市場データAPIだけをブラウザ内で差し替えたダミー検証を実施。12取引日・当日・欠損・未知限月を含め、ローソク足、VP、黄色VWAP、CVD、調整不能の表示を確認した。スクリーンショットには「ダミー検証」を表示した。
- ブラウザ検証の画像IDは `scdiyj`（ローソク足・週VP・CVD）と `ifr8yk`（調整不能）。この2件は観測画像IDであり、保存画像のパスではない。Workspaceへの画像ファイル出力はされなかった。
- 設定APIはダミーにせず実APIを使用。幅9で保存不可、キャンセルでサーバー応答不変、ローソク足・週・RTH・共通基準・刻み4・CVDオフの保存と別コンテキストへの反映を確認。最後に元の長期VP設定値をPUTで戻した。`updatedAt` は保存により更新されるが値は元通り。既存 `/api/settings` はPUTせず、前後の応答がバイト同一。
- 最終POC延長の修正は単体試験10/10・画面全129件・型検査・本番再ビルドで確認した。ブラウザの同じ全経路を繰り返し実行していない。
- メイン最新変更との統合後：安全な初期化・停止処理を残し、専用設定の生成・API配線を追加した。起動試験の一時コピーにも共有設定定義を含めるように修正し、サーバー全157試験・型検査成功。新たな3件の子プロセス試験で、準備完了前の非待受、準備中のSIGTERM、破損時の安全停止、上流停止・HTTP終了・原本バイト不変を確認した。

## ブラウザ・接続の終了

- 実画面撮影後、撮影ブラウザPID3552とcrashpadをSIGTERMで閉じ、ローカルChromiumプロセス0を確認。
- 操作検証ツールはページ・コンテキストを閉じ、ブラウザ切断を報告した。ただし親Chromium PID3820とcrashpadが残っていたため、別途SIGTERMで終了させ、子プロセスも含めローカルChromiumプロセス0を確認した。ページを閉じただけでブラウザ終了と扱っていない。
- 終了後の `/api/status` に検証ブラウザの接続はなし。検証前から存在する外部Chrome156の2接続だけが残っていたため、検証接続と混同しない。外部接続を遮断する設定は行っていない。
- サーバー側にも検証ブラウザの `hub_closed`（peer 3・4、Chrome140、code1001）を確認した。
- 最後に開発ワークフローをSIGTERMで停止。PID3491の消滅、ポート25028の `ECONNREFUSED`、Chromiumプロセス0を確認。停止直前の上流は `stopped` で、開発から外部WSは開かなかった。ワークフロー停止のログはpnpmのSIGTERM終了であり、今回の停止で `server_stopped` の詳細ログが出たとは主張しない。

## 仕様との差分・残る確認

- ユーザー承認により、設定は既存設定への追加ではなく専用設定へ分離した。正本は書き換えていない。
- 本番蓄積データでの日次更新・長期表示、公開側のアクセス制限はこのフォークでは未確認。開発のAPI無効状態を本番状態として扱わない。
- iPad Safari実機での新画面のジェスチャー、長期間蓄積時のブラウザ実メモリ上限は未測定。
- 公開操作はしていない。変更が公開アプリへ届くには、まずメインへのマージが必要。
