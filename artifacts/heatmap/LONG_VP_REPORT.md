# 長期VP：現状と追加指定の整理

この文書は仕様書への転記用の実装報告。正本 `replit.md` と `docs/` の代わりではなく、それらを差し替えていない。
2026-10-29時点のコード、既存 `server/LONG_VP_REPORT.md`、今回のユーザー指定を区別して記載する。

## 1. 結論・実装状況

- **実装済み：蓄積基盤。** 同じ受信サーバー内で、限月別の30分×価格の売買出来高、1分足OHLCと売買出来高、日別の取得範囲・欠損、限月の切り替え記録を保持する。
- **未実装：長期VP画面とその表示API・設定。** 日次／週次VP、価格ライン／ローソク足、週VWAP、週CVD、上部の画面切り替えは、まだ利用できない。
- 長期VPの永続保存先は **PostgreSQL**。長期VP専用のApp Storageオブジェクト名・保存ファイル形式は **ない**。既存ヒートマップのApp Storage保存とは別系統。
- 画面より先に本番蓄積を確認する順序を維持する。共有された本番 `/api/status` には `phase2a.longVp` がなく、`phase2a.vp.state:"complete"` は既存セッションVPである。本番での長期VPの開始・完走を確認できていない。
- 今回は現状報告と指定の記録のみ。アプリの実行コード、DB定義、既存保存、正本、公開設定は変更していない。画面を実装済みとは扱わない。

## 2. 何を、どの期間で集計・保存するか

### 実装済みのデータ

| データ | 粒度・キー | 保存先・用途 |
|---|---|---|
| 売買出来高 | 取引日・限月・30分区間・0.25ポイント価格。買い／売りを別々に合計 | `long_vp_volumes`。将来の日次／週次VP、週VWAPの元データ |
| 価格足・売買出来高 | 取引日・限月・1分区間。OHLC、買い／売り、最初／最後の約定時刻 | `long_vp_minutes`。将来の価格ライン／拡大足／週CVDの元データ |
| 取得記録 | 取引日ごとの始終端、取得済み範囲、欠損範囲と理由、完了フラグ、約定件数、更新時刻 | `long_vp_sessions` |
| 限月記録 | 切り替え時刻 `since_us` と限月名 `contract` | `long_vp_rolls` |

日別の集計元を保存しているのであり、日次VP・週次VP・VWAP・CVDの完成した表示系列を別途保存しているわけではない。
価格別出来高は30分区間ごとの疎な行で、取引のない価格に0行を敷き詰めない。

- 内部の価格は整数ティック（1ティック＝NQの0.25ポイント）。価格調整はしない。
- 内部の時刻は整数Unixマイクロ秒。30分・1分の開始時刻はUnix時刻で切り下げる。
- 取引日はAmerica/New_Yorkの壁時計で前日18:00〜当日17:00、半開区間。17:00〜18:00は休止。現行のカレンダー処理自体は土日・祝日を除外せず、日付ごとに取得を試す。市場カレンダーを実装済みとは扱わない。
- 集計単位に限月が含まれるため、新旧限月の出来高・1分足は混ざらない。同じ1分内で替われば、限月別に2行になる。
- 日次／週次、ETH／RTH、表示価格刻みへの再集約は画面実装時の処理で、現状では未実装。

### 取得・確定・保持

1. 本番判定は `REPLIT_DEPLOYMENT=1`。加えてDB接続が必要。開発Runでは蓄積しない。開発から上流WebSocketを開かず、実データの検証はRESTに限る。
2. 起動時、DBの取得記録・限月記録と `/symbols` の現行情報を照合し、直近7日内の終了した取引日の不足範囲をRESTで取得する。
3. 日次は **17:10 America/New_York**。夏冬時間でUTCの実行時刻が変わる。毎回、回収可能な7日内の不足も確認する。初回取り込みと再起動時の不足回収もDBへ書くため、厳密に「全運用で1日1回しか書かない」わけではない。
4. 終了した日の確定値にはRESTだけを使う。当日ライブのメモリ集計をそのまま確定しない。
5. 1日分の集計と取得記録を同じDBトランザクションで保存。失敗時はロールバックし、既存の完了済みの日を未完了の結果で上書きしない。
6. RESTは最大15分窓・順次取得。`/ticks` の上限100,000行に達した窓は分割して再取得する。7日分の生約定を全件メモリに保持しない。
7. 当日暫定値はメモリのみ。起動前の範囲は5分の成熟待ち後にRESTで補うが、接続境界には `seamIncomplete:true` を付ける。
8. 回収不能範囲は欠損として残す。7日を超えた欠損は `recoverable:false`。有効な0件応答と通信失敗は区別する。提供元内部の未申告の欠落まで保証するものではない。
9. 保存済みの長期集計を自動削除する保持期限は現状ない。8日より前の表示に使えるのは、自前で蓄積できた範囲だけ。

## 3. App Storageとの区別

長期VPに新しいバケット、プレフィックス、ファイルは追加していない。長期VPは上記PostgreSQL4表に保存する。
バケットIDなどの機密値は報告に含めない。

既存ヒートマップは従来どおり、本番では `prod/` の下に時間別の板列と生約定を保存する。
板列は `prod/columns/NQ/1s/YYYY-MM-DD/HH.bin.gz`（gzip圧縮バイナリ）、約定は `prod/trades/NQ/YYYY-MM-DD/HH.jsonl.gz`（gzip圧縮JSONL）。日付・時はUTC。
取得範囲は `prod/coverage.json`、既存画面設定は `prod/settings.json`。
具体的な時間別キー生成は `server/src/store/local.ts::file` と `server/src/store/app.ts::object` を参照する。
これらは長期VP専用保存ではなく、今回も変更・移行・廃止していない。

## 4. 保存量・メモリ量の目安と未測定事項

### 保存行数

- 1限月・通常の23時間取引日では、1分足は最大約1,380行。約定のない分は行がなく、限月切り替えの分は別行になる。
- 30分枠は通常1日46枠。価格別行数は「各枠で約定があった価格数」の合計であり、約定件数そのものではない。複数限月なら限月別に数える。
- 仮に各枠1,000価格なら46,000行／日。これは容量計算のための仮定で、実測ではない。
- 日次取得記録は1行／取引日、限月記録は確認した切り替え時刻ごと。週ごとの集計を二重保存する行はない。

### バイト数の計算上の下限

30分×価格の行数をV、1分足行数をMとすると、数値カラムのデータ部分だけで約 `28V + 56M` バイト。
上の仮定では約1.37MiB／取引日。これは限月名・日付文字列・行ヘッダー・アラインメント・主キー索引・取得記録・WAL・空き領域等を除くため、**実際のDB使用量ではない**。
本番容量は4表と索引を含むDB実測が必要で、月額費用や保存年数を保証できない。

### メモリ

- 通常は当日暫定の30分×価格Mapと1分足Map、日別の取得記録、限月一覧を保持する。
- バッチ中は処理中の1日分の集計と、REST窓の応答も重なる。保存時にはMapの値を配列へ展開し、JSON化するため、その分も一時的に増える。
- JavaScriptのMap・文字列キー・オブジェクトにはDBの数値カラムより大きい管理領域がある。上のDB下限からRSSを算出することはできない。
- 過去表示用の読込キャッシュはまだ実装していない。キャッシュの期間・上限・失効方式を実装済みとして記載しない。
- 既存報告のREST1分標本は149約定、価格別41行、1分足1行。終日・7日・長期表示の代表測定ではない。
- 共有された本番状態のRSS約331MiBはサーバー全体の値で、長期VP稼働の確認もない。長期VPの増分メモリとして流用しない。
- 本番の初回7日取り込み、日次バッチ、表示時キャッシュの容量・最大RSS・CPU・時間は未測定。

## 5. 画面配置・表示仕様（指定済み、未実装）

| 場所 | 出すもの |
|---|---|
| 同じサイトの独立した長期VP画面 | 既存ログイン・サーバーを共有。ヒートマップ自体は出さない |
| 上部 | ヒートマップ／長期VPの画面切り替え |
| 左ツールバー | 既存と同じ部品の設定・表示リセット |
| 上段（初期約75%） | 価格ラインまたはローソク足。背面に日次／週次VP、重ねて週VWAP |
| 各期間の左端 | 右向きVP、VA70%の水色縦線。VAH・POC・VALの横線・価格ラベル。POCを次期間へ少し延長 |
| 下段（初期約20%） | 週CVDの線。上下の週区切りを揃える |
| 最下部 | 上下共通の時間軸。表示は日本時間、集計区切りはET |
| 上下境界 | ドラッグで比率変更。週CVDを非表示にすると下段を消して上段を広げる |

- 価格は1分足を元にズームに応じた粒度へ切り替える。日次／週次VPの切り替えは手動のみ。
- 日はETH（前日18:00〜17:00 ET）／RTH切り替え、週は日曜18:00〜金曜17:00 ET。
- VP幅は期間別正規化を初期値とし、全期間共通基準にも切り替える。表示価格刻みは最小0.25ポイント。POC・VAは刻みによらず0.25ポイントで計算する。
- 週VWAPは30分×価格の出来高から `Σ(価格×出来高) / Σ出来高` を計算し、週の開始でリセット。標準偏差バンド・前週延長は入れない。
- 週CVDは1分の買い−売りを累積し、週開始で0へ戻す。今週分は1分ごとに更新する。
- 欠損のある期間はVPが不完全だと分かる表示を行う。
- 価格、VP、装飾線／ラベル、VA縦線、POC延長、VWAP、CVDを設定画面で個別にオン／オフ。設定はサーバーで共有する。

VPの幅の割合、POCの延長量、未指定の表示詳細は、この報告で新たな数値を決めていない。

## 6. 今回確定した乗り換え境界の扱い

以下は添付の「表示時に新旧限月差で調整する」を上書きする最新のユーザー指定。実価格のままであり、調整差は取得・保存・計算しない。

| 対象 | 扱い | 現状との差 |
|---|---|---|
| 日次・週次VP | 限月別に集計し、新旧を同じVPへ合算しない。期間途中で替わった期間は今の限月の分のみ表示。旧限月分は別に保持し、切り替え閲覧の可否は後で決める | 保存元は既に限月別。期間VPの表示・選択処理は未実装 |
| 価格ライン | 境界では線をつながない | 長期画面の描画は未実装 |
| ローソク足 | 境界をまたぐ足は旧限月・新限月の2本に分ける | 1分足は既に限月別。表示用の長い足への再集約も限月をまたがない実装が必要 |
| 週VWAP | 週開始に加え、限月が替わったところでも計算し直す | 計算・描画は未実装 |
| 限月判定 | `/symbols` の `contract`・`contractSince` と約定時刻を対応づける既存方式 | 既存の `contractAt` を維持 |
| 境界時刻 | ログと `/api/status` に出す | 下記の既存出力で対応済み。新しい別名の項目は足していない |

`contractSince` より前は旧限月、境界時刻ちょうどから新限月の半開区間として扱う。記録がなく判定できない時刻をカレンダーから推測しない。
ライブtick・book、履歴の各行に限月が直接入っている前提ではない。
現行実装の限月情報更新は起動・日次バッチ時で、ライブの即時検出は保証しない。今回の指示は既存方式を許容したもので、監視頻度を勝手に変更する許可とは扱わない。

「今の限月だけ表示」は今回指定された期間途中の切り替えを対象とする。限月をまたがない過去期間まで全て非表示にする指定へは拡大解釈しない。
週CVDを限月境界でリセットする追加指定はないため、VWAPのルールを類推適用しない。

### 境界の既存出力先

- `server/src/long-vp/service.ts::run`：`long_vp_contract` ログに `contract` と `sinceUs`。メタデータを確認した時点の出力であり、境界の瞬間のイベント検出ではない。
- `LongVpService.snapshot` → `GET /api/status` の **`phase2a.longVp.contracts[]`**：`contract` と `sinceUs` の一覧。
- `sinceUs` は整数Unixマイクロ秒。`contractSince` のマイクロ秒未満は切り捨てる。ログの出力時刻と限月の境界時刻を区別する。
- 保存済みの境界は `long_vp_rolls`。未知・矛盾するメタデータは停止または欠損として扱う。

## 7. 新しく足したメッセージ・API・設定

### 蓄積実装で追加済み

- 新規RESTルートはない。既存 **`GET /api/status`** の `phase2a.longVp` を追加した。
- 有効時は `enabled, state, error, timezone, dailyTime, nextBatchUs, progress, contracts, sessions, provisional` を返す。
- `state` は `idle / running / waiting / blocked / stopped`。無効時は `enabled:false` と `production_only` または `database_url_missing` の理由を返す。
- `sessions` は日付、始終端、coverage、gaps、complete、trades、updatedUsを含み、欠損には回収可否を付ける。`provisional` は日付・件数等と `authoritative:false, seamIncomplete:true` を含む。実データ系列そのものを返す表示APIではない。
- 既存WebSocket `/api/ws` のメッセージ形式・statusは変えていない。長期VP専用の購読・配信メッセージはまだない。
- 主な追加ログ：`long_vp_disabled`, `long_vp_contract`, `long_vp_window`, `long_vp_gap`, `long_vp_session_saved`, `long_vp_batch_done`, `long_vp_batch_failed`, `long_vp_provisional_gap`, `long_vp_provisional_ready`, `long_vp_db_idle_error`。これらはサーバーログであり、ブラウザ向けWSメッセージではない。
- 外部REST利用は `/v1/symbols` と `/v1/ticks`。ブラウザからは呼ばない。
- 既存 `TICKSTREAM_API_KEY` と本番DB接続をサーバーで使う。17:10 ET・取得窓等はコード内の運用値で、ユーザー表示設定には追加していない。

### 未追加

長期VPデータ取得API、過去表示用キャッシュ、長期VP画面URL、画面切り替えUI、長期VP表示設定キー／保存形式はまだない。
既存ヒートマップの設定API・設定バージョンは今回変更していない。
